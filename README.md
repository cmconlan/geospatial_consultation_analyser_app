# Geospatial Consultation Analysis App

An interactive map of the themes raised in planning-application consultation responses across
Brighton & Hove, showing where issues concentrate, how people feel about them, and how they change
over time.

> **All consultation data in this repository is synthetic.** Applications, responses and the
> patterns within them are generated by `python/generate.py`. Neighbourhood names are used only to
> place the fictional data plausibly on the map.

## Concept

In a production setting, raw consultation responses would pass through an LLM extraction step that
labels each response with themes, stance and sentiment. This demo simulates the *output* of that
step, so the schema in `data/synthetic/` matches what such a pipeline would produce.

```
raw responses ──► [LLM theme / sentiment extraction] ──► labelled responses ──► H3 aggregation ──► web app
                        (simulated in this demo)          data/synthetic/        (next step)
```

## Running the data pipeline

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python python/fetch_boundary.py     # downloads the ONS boundary to data/raw/
python python/generate.py           # writes the synthetic dataset to data/synthetic/
python python/check_synthetic.py    # summary tables + data/synthetic/checks/overview.png
python python/aggregate.py          # H3 aggregates + app data to web/public/data/
python python/check_aggregates.py   # 2D hex preview, e.g. --theme construction_disruption --res 9
```

## Running the web app

```bash
cd web
npm install
npm run dev        # development server with hot reload
npm run build && npm run preview   # the exact build that GitHub Pages serves
```

Both serve the app under `/geospatial-consultation-analysis-app/`, matching the GitHub Pages path.
Pushing to `main` triggers `.github/workflows/deploy.yml`, which builds `web/` and publishes it.
Basemap: [OpenFreeMap](https://openfreemap.org) Positron style, © OpenMapTiles, data © OpenStreetMap contributors.

## Web data (`web/public/data/`)

The app loads *monthly building blocks* rather than pre-baked views: for each H3 cell, theme and
month there is a response count, a sentiment sum and stance counts. The browser sums these over
the selected time window(s), so mean sentiment and change scores can be computed for any period
without a server.

| File | Contents |
|---|---|
| `aggregates_r8.json`, `aggregates_r9.json` | columnar rows of (cell, theme, month, n, sentiment_sum, n_object, n_support), plus the cell list |
| `applications.json` | per-application details and sample snippets for the drill-down panel |
| `themes.json`, `boundary.geojson`, `meta.json` | lookups, outline and provenance |

Each response counts once towards "All themes" and once towards each theme it is labelled with at
confidence ≥ 0.5.

## Synthetic data

| File | Grain | Key fields |
|---|---|---|
| `applications.csv` | application | id, location, type, submitted date, status |
| `responses.csv` | response | application id, received date, respondent type, stance, sentiment (−1 to 1), text |
| `response_themes.csv` | response × theme | theme, confidence, is_primary |
| `themes.json` | theme | id, label |
| `scenarios.json` | scenario | the planted patterns (ground truth for validating the app) |

Planted patterns include steady hotspots (heritage in Kemptown, HMOs along Lewes Road), a seasonal
pattern (night-time economy in the Lanes), polarised tall-building schemes (Hove seafront, the
Marina), a fading regeneration consultation (London Road) and an emerging issue (construction
disruption along Western Road from March 2026).
